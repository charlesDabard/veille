La veille, étage par étage

Le contenu descend : déclencheurs, cerveaux, récolteurs, base, puis ce que tu lis. Glisse pour tourner, molette pour zoomer, clique un bloc pour sa fiche. Les blocs en pointillé appartiennent au setup de l'auteur, pas à ce dépôt.

  • Dans ce dépôt
  • Extras, en l'état
  • Hors dépôt, chez l'auteur

La scène 3D n'a pas pu démarrer (WebGL absent ou three.js injoignable).
Le guide écrit reste lisible en dessous : il ne dépend d'aucun script.

Installer

Trois commandes, aucun compte, aucune clé. Il faut git, curl, jq, python3 et yt-dlp. 

git clone https://github.com/charlesDabard/veille.git
cd veille
bash install.sh

install.sh fait quatre choses, dans cet ordre : il lie ~/.claude/skills/veille vers le skill/ du dépôt, il crée la base de connaissances dans ~/veille-kb, il copie les listes de sources d'exemple dans ~/.config/veille/, et il compile ytkb.

Relance-le autant que tu veux : un second passage ne modifie rien. Si un lien veille existe déjà chez toi, il refuse de l'écraser et te dit exactement quoi faire. Et si Rust manque, il lie quand même la skill, installe le reste, et te donne la commande qui manque : seule la source YouTube est indisponible.

Ensuite, avant la première récolte :

bash skill/doctor.sh

Un tableau SOURCE / ÉTAT / DÉTAIL / RÉPARATION, en lecture seule, sans une seule requête réseau. Toute ligne KO porte la commande exacte qui la répare. SKIP veut dire « source optionnelle désactivée » : la veille tourne sans, et le rapport le dit.

Premier run

Dans ton agent, depuis le dossier de ton choix :

/veille serveurs MCP

Le skill commence par une question, jamais par une récolte : YouTube seul, tout, web seul, ou choix fin source par source. Il dérive ensuite deux ou trois requêtes du sujet, il te montre ce qu'il a trouvé avec les titres, et il attend ta sélection. Rien n'est téléchargé sans ton accord.

Les questions passent par l'outil de question de l'agent, pas par du texte libre : dans Claude Code c'est AskUserQuestion, dans OpenCode c'est l'outil question. C'est ce qui rend la sélection rapide au clavier.

Un terme polysémique se désambiguïse avant la récolte complète. Le skill sonde d'abord cinq résultats et lit les titres : sept faux positifs distillés pour rien coûtent bien plus qu'une requête de sonde.

Ce que produit la base

Tout atterrit dans $VEILLE_KB si la variable est posée, sinon ~/veille-kb. Un dossier par sujet : 

~/veille-kb/
├── _bruts/          transcripts et articles tels quels, horodatés
├── notes/           une note par source, en français, avec sa pertinence
├── SYNTHESIS.md     la synthèse du sujet, réécrite à chaque run
└── _index.md        les sources déjà ingérées, l'anti-doublon

Chaque note commence par un front-matter qui porte le titre, l'URL, la source et la date de distillation, puis une section ## Pertinence notée sur 5. C'est cette note qui permet de trier plus tard, quand la base aura cent notes et que tu ne te souviendras plus de pourquoi tu avais gardé celle-là.

La synthèse n'est pas un journal : elle est réécrite, pas complétée. Une information périmée sort, une contradiction se tranche, une section qui n'a plus rien à dire disparaît. C'est le travail que personne ne fait à la main.

L'incrémental

Relancer /veille serveurs MCP la semaine suivante ne retélécharge rien. _index.md liste les identifiants déjà ingérés, et seuls les nouveaux passent. Sans ça, la base grossit en doublons et la synthèse devient illisible.

Chercher

Deux façons de poser la question :

cherche dans ma veille : les serveurs MCP gèrent-ils OAuth ?
d'après ma veille, qu'est-ce qui a changé sur les agents cet automne ?

La réponse vient uniquement de la base, avec les notes citées. Si la base ne contient pas la réponse, le skill le dit au lieu d'inventer : c'est la différence entre une base de connaissance et un moteur de recherche qui te noie.

Linter

lint ma veille

Un contrôle de santé en lecture seule, par sujet : contradictions entre deux notes, affirmations devenues fausses, notes orphelines qu'aucune synthèse ne cite, liens morts. Le rapport sort dans _lint-reports/, daté.

C'est le mode qui garde la base honnête. Une base qui ne se relit jamais accumule des vérités de l'année dernière avec l'air d'être d'aujourd'hui.

Ajouter une source

Trois niveaux, du plus simple au plus coûteux. Commence toujours par le premier.

1. Une liste, si la source est un flux

~/.config/veille/feeds.txt pour du RSS ou de l'Atom, ~/.config/veille/channels.txt pour des chaînes YouTube (langue, tabulation, URL de la page vidéos). Une ligne par source, # pour commenter. Aucun code à écrire.

2. Un script de récolte, si la source a une API

Regarde skill/fetch_feeds.py : c'est le plus court des récolteurs, et il suit la même forme que les autres. Il lit la liste, interroge la source, écrit du NDJSON sur la sortie standard, et laisse la distillation au skill. Un récolteur ne juge rien, il rapporte.

3. Une note de méthode, si la source demande une session

Certaines sources ne s'ouvrent qu'avec un compte, un cookie ou un outil dédié. C'est le cas de toutes les sources de skill/extras/sources-avancees.md : le fichier décrit l'accès, les conditions et les pièges, il ne promet pas que ça marchera chez toi.

Faire ta propre skill

Le skill n'est pas magique : c'est un fichier markdown avec un front-matter, lu par ton agent. Le champ description dit quand le déclencher, le corps dit quoi faire. Le reste, ce sont des scripts que le corps appelle.

Pour changer le mot magique, une seule ligne à toucher : le description de skill/SKILL.md. Remplace /veille par ce que tu veux, par exemple MON KEVIN, et le skill répondra à MON KEVIN serveurs MCP. Aucun chemin à modifier : la base est ~/veille-kb ou $VEILLE_KB.

Pour un autre domaine, la méthode qui marche est de garder les mécanismes et de changer la politique : où ranger, quoi distiller, comment fusionner. Les récolteurs, eux, se réutilisent tels quels.

Ce qui est garanti, ce qui ne l'est pas

Partie État Ce que ça veut dire
skill/SKILL.md et les scripts du cœur Testé YouTube, Google News, Hacker News, GitHub, Reddit, flux RSS, X par URLs collées, recherche web. C'est là que vivent les 80 % du travail, et c'est maintenu.
skill/doctor.sh Testé Lecture seule, aucune requête réseau, une commande de réparation par panne.
skill/extras/ En l'état Chine, Corée, Russie, Yandex, et l'automatisation par launchd. Tourne sur la machine de l'auteur, sous macOS, avec des clés et des sessions de navigateur. Non garanti ailleurs.
~/veille-kb À toi Dépôt git local. Rien ne sort de ta machine, rien n'est poussé sans que tu le décides.

La règle est simple : ce qui est dans le cœur est promis, ce qui est dans extras/ est offert tel quel. skill/extras/README.md dit, pour chaque pièce, ce qu'il faut pour la faire tourner. Lis-le avant de l'activer.
